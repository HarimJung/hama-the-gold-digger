# 엔진 v2 설계 — 한 줄로 이어진 대본·모션 엔진 (11/07 밤, 승인 전)

하림님 11/07: «하드코딩으로 하나씩 고치지 말고 엔진을 처음부터 끝까지 다 잡아라. 1초 안에 훅, 저장·포모, 뭘 얻는지, kallaway 9칸, 디자인은 일관되되 눈을 확 사로잡게, 멈춤·말만·싱크·줌 어긋남을 전부 공식으로. 레퍼로 충분하다. 규칙 네 곳·입력 관문 없음 같은 구조 문제를 고쳐라.»

## 지금 구조와 병 (코드로 확인한 것)

| 지금 | 병 |
|---|---|
| find.py → hook.py → director.py(모델 1회, 자유 문장 14~18줄) → GRAMMAR least_used 로 부품 → build_rail → render | 단계마다 다른 모듈, 입력 검사는 felt 하나. plain·why 가 비어도 씀 → 어제 47편은 되고 오늘 4편은 안 됨 |
| 규칙이 hooks.json · prompts/rail.md(산문 40줄) · director.py(정규식·문턱) · review() 네 곳 | 한 곳 고치면 다른 곳과 어긋남. 문제가 보일 때마다 정규식 한 줄 추가 = 하드코딩 |
| 대본이 자유 문장 | «그게 뭔지 먼저 말했나», «뭘 얻나»를 기계가 못 봄. 관문은 토큰(숫자·금지어)만 |
| 그림 = 역할별 후보 3~6개 중 덜 쓴 것 | 다양성은 36부품 중 6개 목록에 갇히고, 뜻과 무관(비용 아래 성장 곡선). 71가족 중 ● 26, 쓰이는 건 그중 절반 |
| 싱크 = 부품마다 `at` 한 단어 | 줄이 2~3개인 장면은 한 번 움직이고 멈춤. 차트·줌은 정규식으로 줄을 찾다 빗나감 |
| 검수 = 글자 관문 + 하림님 눈 | 영상을 기계가 안 봄(hyperframes check 미사용). 멈춤·빈 프레임·소리 크기 미측정 |

## v2 원칙 다섯

1. **한 소스.** `엔진/spec/` 에 칸·가족·훅·발음·피부 토큰을 두고, 프롬프트와 관문을 거기서 만든다. 산문 규칙과 정규식은 없앤다.
2. **입력 계약이 먼저.** 재료가 하나라도 비면 그 자리에서 멈춘다. 뒤 단계는 완전한 편만 받는다.
3. **대본은 칸이다.** kallaway 9칸에 뜻 필드가 붙는다. 모델은 칸을 채우고, 기계가 뜻을 검사한다.
4. **그림은 뜻과 에너지가 정한다.** 데이터 모양이 가족을 고르고, 에너지 곡선이 세기를 고르고, least_used 는 같은 모양 안에서만 섞는다.
5. **기계가 먼저 본다.** 낯선 사람 읽기(모델) + hyperframes check + 우리 지표(정지·줄 반응) → 통과한 편만 하림님께. 대지 1장 + 랜덤 3편.

## 설계

### 0. spec (한 소스)
- `spec/script.json` 칸 9개: hook · lockin · body1 · rehook · body2 · rehook2(trap) · body3? · closing · ending(check|myrow|cta). 칸마다 `says`(한 문장 요지) · `lines`(1~2) · `number`(numset 안) · `shape`(pair|path|growth|single|list|none) · `energy`(1~3) · `anchor`(움직일 단어) · 관문(아래).
- `spec/motion.json` 가족 71(fx-목록 그대로): id · 뜻 태그 · 받는 shape · energy · 길이 · 구현 부품 · 상태 ●◐○ · 출처. 부품 하나 = 가족 하나. 새 가족은 여기 한 줄 + parts 함수 하나.
- `spec/hook.json`(지금 one_second 그대로) · `spec/say.json`(발음) · 피부는 skin.css :root 그대로.
- rail.md 는 spec 에서 생성한다(템플릿). director 의 정규식·GRAMMAR·문턱은 spec 필드로 옮기고 지운다.

### 1. 입력 계약 (관문 0)
편에 있어야 하는 것: subject{name, what_it_is} · fact{num, 출처 인용} · felt{$} · plain{what, so_what, do} · why(티커 편) · deliverable(받아갈 물건) · charts(티커 편). `run.py` 가 빠진 이름을 찍고 멈춘다. find.write 가 plain·why 를 반드시 만든다(11/07 넣음).

### 2. 칸 대본
- 1초 훅: 칸 1 = 공식(이름+잃은 $+질문), 0초 프레임에 이름·숫자·도장이 이미 있다(10 첫 장면 중 택1). 칸 2 약속. 칸 3 lock-in 한 줄.
- body1 첫 줄 = what_it_is. 모든 숫자는 numset. closing = felt 다시. 끝 = plain.do 또는 받아갈 물건.
- 관문(결정론): 그게-뭔지-먼저 · 숫자 전부 numset · closing 에 felt · 끝에 do/물건 · 칸당 ≤2줄 · 줄당 ≤12단어 · 금지어·매수콜. FAIL 은 지금처럼 넷(지어낸 숫자·매수콜·felt 없음·금지어)만, 나머지는 자동 재작성 2회 뒤 경고.
- **낯선 사람 읽기**: 싼 모델이 대본만 읽고 «이게 뭐야 / 숫자 하나가 뭐야 / 나는 뭘 해»에 답한다. plain.what·felt·do 와 다르면 그 차이를 붙여 다시 쓴다(최대 2회). 이게 하림님 «무슨 말인지 모르겠다» 관문이다.

### 3. 그림 고르기
- 칸의 shape → 받는 가족 집합(모양이 맞는 것만). pair → 덤벨·compare·wipe·stack·split · path → 폭포·receipt·funnel·shrink · growth → coins·counter·odometer·multiply·clock·line · single → stamp·swap·strike·odometer · list → checklist·table·notify · none → 글자 가족(T4·T8·T10…).
- 에너지 곡선(spec): hook 3 → lockin 2 → body1 2 → rehook 3 → body2 2 → trap 3 → closing 2 → cta 3. 가족마다 energy 가 있어 곡선에 맞는 것만.
- 다양성 제약(편 단위): 전환 ≥3종 · 무거운 것 ≤2 · 같은 가족 3장면 안 반복 금지 · 최근 6편과 첫 장면·끝 장면 다르게. least_used 는 이 집합 안에서만.
- 차트는 뜻으로: 주가 창은 «sits below·fell·zoom» 칸(spec anchor), 줌아웃은 같은 티커 짧은→긴 창, 티커 둘이면 둘째 창(11/07 넣음).

### 4. 싱크 계약
- 줄마다 시각 사건 ≥1: 칸의 anchor 단어에 부품의 움직임, 부품이 못 받는 줄은 엔진이 줄 칩·강조 상자를 얹는다(11/07 줄 칩). 측정은 «줄 반응 비율»(REACT_MIN .6 → spec).
- 카메라·푸시인 같은 «멈춤 가리기»는 금지(hyperframes motion.md 안티패턴).

### 5. 검수 루프 (자동)
build 뒤: hyperframes `check --json`(dead_stretch·first_frame_empty·layout·contrast, 자막은 captions 호스트) + review(정지·줄 반응·칸 관문) + 낯선 사람 읽기 → 실패면 director 가 같은 대본으로 매핑만 다시(--redirect) 최대 2회 → 그래도면 원장에 FAIL. 통과 편만 대지+랜덤 3편으로.

### 6. 납품 층
ffmpeg-skill: loudness −14 LUFS(지금 −19.4) · export reels · check --content · look --safe reels. 설치는 하림님 `npx ffmpeg-skill`.

### 7. 한 파이프라인
`run.py make <key>` = find → hook → 관문0 → 칸 대본 → 낯선 사람 → 그림 → build → check → 납품. `run.py rebuild --all`. 원장 하나(motion-ledger + hooks-ledger 합침). 단계는 JSON 입력→JSON 출력 함수.

## 지우는 것
director 의 GRAMMAR dict · chart_tgt 정규식 · 쪼개기 휴리스틱 · opener_data 정규식 뭉치 · review 의 산문 경고 · rail.md 산문 규칙 · build_rail 의 임시 다리들. 전부 spec 필드로.

## 순서 (단계 끝마다 대지 1장 + 랜덤 3편, 하림님 판정)
1. spec 3파일 + 관문0 + 칸 대본 프롬프트 + 낯선 사람 읽기 → SOXL 1편으로 시범 (하루)
2. 그림 고르기(shape·energy·다양성) + 싱크 계약 + 검수 루프 → 랜덤 5편 (하루)
3. 47+4편 전부 v2 로 재생산(모델, 약 1시간) + ffmpeg-skill 납품 층 (반나절)
4. 그 뒤 라운드마다 가족 7개씩 ○→● (레퍼 fx-목록 순서: 첫 장면·숫자·하마 물건·UI). director 는 안 건드린다 — motion.json 한 줄 + 부품 함수 하나.

## 레드팀 먼저
시작 전에 이 문서를 레드팀 에이전트에 넣어 구멍을 받고, 잡힌 것을 아래에 적는다.

## 레드팀 결과 (11/07 밤, 검증 12개) — 위 설계에서 틀린 것

1. **천편일률의 진짜 원인은 least_used 가 아니라 GRAMMAR 후보 집합이 겹치는 것.** myth·catch·loss·rehook·closing 다섯 역할이 전부 {swap·strike·stamp(+odometer·shrink)} 를 받는다. 원장 53편 실측: 몸통 칸 277개 중 stamp 38·strike 37·swap 36 = **40%**, 데이터 없는 장면 159/478(rehook 57/102 는 자막만). 위 설계의 shape 매핑(single → 같은 네 부품)은 이걸 그대로 복제한다.
2. **«에너지 곡선»은 측정 정의가 없다(vibes).** 가족마다 energy 1~3 을 손으로 적는 건 하드코딩을 JSON 으로 옮긴 것. 측정 가능한 건 이미 있는 «줄 반응 비율»·«정지 초» 둘.
3. **«낯선 사람 읽기 → 재작성 2회»는 FAIL 넷 규칙 위반**(재작성 = 떨어뜨리기). 비용 편당 모델 최대 5회 ≈ 10분. 경고로만, 답 3개를 원장에 기록.
4. **모델이 채우는 shape·anchor·says 는 믿을 수 없다.** shape 는 data 키가 이미 말한다. anchor 는 지금도 506개 중 203개(40%)가 줄 번호 폴백. says 는 기계가 검사 못 함.
5. **싱크 계약은 모델 없이 된다.** 줄마다 toks·t0 가 있고 숫자 줄은 «줄 칩»(11/07) 이 있다. 남은 건 숫자 없는 줄 → *별표* 단어 강조를 부품 위에 얹으면 끝.
6. **관문 0 이 새 FAIL 다섯을 더한다**(why·deliverable·charts·so_what·do). why 없는 티커 편 ≥3, plain 없는 6편이 멈춘다. plain·felt·subject 만 자동 채움, why·deliverable 은 경고+기본값.
7. **51편 재생산은 `--redirect`(모델 0회) 를 죽인다**(GRAMMAR·data_for 를 지우면 made_by.parts 를 못 읽음) → 이후 규칙 한 줄 고칠 때마다 모델 50분. 원장 합치기는 얻는 것 없음. 캐러셀·사이트·MP4 51개 전부 다시(1.5시간).
8. **동결 위반 위험.** 승인된 SOXL 정답 편은 어느 post.json 에도 고정돼 있지 않다(rail_prev 두 세대뿐). 재생산 전에 `snapshots/` 에 rail{}+MP4 해시를 박아야 비교 기준이 남는다.
9. **다양성 제약 넷은 이미 충족**(같은 부품 연속 0, 편당 가족 평균 9.8, 전환 6종 고른 분포). 체감 단조로움은 ①의 글자교체 40% 와 무데이터 장면 159 에서 온다. 가족 실측 ● 31 · ◐ 8 · ○ 39 — ○ 를 ● 로 올리지 않으면 제약을 더해도 고를 게 없다.
10. **hyperframes check 는 거짓양성이 커서 판정에 못 쓴다**(canvas_overflow 17 등). 경고 집계로만. dead_stretch 는 captions 호스트 처리가 맞는지 실측부터.
11. **rail.md → spec 생성은 산문 30줄을 JSON 에 넣는 것뿐.** 뜻 판정 정규식(chart·opener·CALL)은 필드가 못 된다. «한 파일로 모으기»와 «없애기»는 다르다.
12. **더 싼 길(새 모듈 없이)**: 아래 v2.1.
