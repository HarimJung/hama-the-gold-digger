## 새로 가져온 것

### 1. 훅

**하마 정본은 그대로다**: 이름 + 잃은 $ + 얻는 질문 (11/06 승인, [[hama]] 엔진 hook.py). 아래는 꼴을 바꿀 때 고르는 서랍이지 새 관문이 아니다.

후킹 8공식 (B): ① 핵심 먼저 ② Before/After ③ 고정관념 뒤집기(반전을 빼면 당연한 말이 되면 진짜) ④ 공감 ⑤ 돌발 ⑥ 비주얼·오디오 ⑦ 손해·부정(과하면 안 됨) ⑧ 권위(문장 중간에). 하마 정본은 ⑦+①.

훅 3박자 (B): 충격 고백 → 공감 문제 → 재정의. «이거 보고 소름 돋았습니다» → «~한 적 있으시죠?» → «사실은 ~ 때문입니다». 훅 안에 «저장해 두세요»를 먼저 넣는다.

4금기 (B), 하나라도 걸리면 폐기: 과함(역할 겹치는 요소) · 어려움(초등 6학년 기준) · 훅을 회수 안 함 · 재미없음.

26유형, 목적별 (C):

| 이럴 때 | 묶음 | 유형 |
|---|---|---|
| 낸 결과·사례가 있을 때 | 결과로 끌기 | 결과 강조 · 성과 인증 · 변화 스토리 · 기간 성과 · 브랜드 성장 사례 · 가능성 확장 |
| 흔한 말과 다른 얘기 | 상식 깨기 | 상식 파괴 · 반대 의견 · 현실 직시 · 비밀/희소성 |
| 손해 보기 싫은 마음 | 멈추게 하기 | 경고 · 흔한 실수 · 필수 개념 강조 · 충격 통계 |
| 끝까지 봐야 답이 나올 때 | 궁금하게 하기 | 실험 결과 · 디테일 분석 · 새로운 기회 발견 · 트렌드+문제 제기 · 시장 기회 |
| 댓글·팔로우를 늘릴 때 | 공감 얻기 | 감정 공감 |
| 저장을 부르는 정보형 | 쉽게 알려주기 | 전문가 압축 · 해결책 제시 · 작은 행동 큰 결과 · 빠른 이해 · 기능 활용 · 쉬운 방법 |

하마에 맞는 템플릿 (C 원문, 재테크 예시 포함):
- 가능성 확장: «[대상]도 [큰 결과]가 가능할까요? 이 사람은 [기간] 만에 [더 큰 결과]를 냈습니다.» 예: «월급 200만 원 직장인도 1억 모을 수 있을까요? 이 사람은 4년 만에 해냈습니다.»
- 필수 개념 강조: «이 개념을 이해하지 못하면 결코 [원하는 결과]를 얻을 수 없습니다.» 예: «‘복리’ 개념 모르면 돈은 절대 안 모입니다.»
- 빠른 이해: «[짧은 시간]만 주시면 [비싼 대안]보다 쉽게 [복잡한 주제]를 알려드릴게요.» 예: «1분만 주시면 유료 강의보다 쉽게 ETF를 설명해드릴게요.»
- 경고: «[과정]을 배우기 전까지는 [활동]을 시작하지 마세요.»
- 흔한 실수: «[주제]에서 피해야 할 가장 흔한 실수 [숫자]가지를 소개합니다.»
- 충격 통계: «[분야]의 [높은 비율]이 [부정적인 속성]을 가지고 있습니다. 꼭 봐야 할 수치가 있습니다.»
- 실험 결과: «[행동]을 [기간] 동안 하면 어떻게 될까요? 결과는 [형용사]입니다.»
- 디테일 분석: «이 [콘텐츠]가 [엄청난 수치]를 기록한 건 바로 이 [작은 디테일] 덕분입니다.»
- 반대 의견: «인기 없는 의견일 수도 있지만, 저는 [흔한 조언]의 반대가 맞다고 생각합니다.»
- 현실 직시: «우리는 언제 [주제]의 [부정적인 결과]를 인정하게 될까요?»
- 비밀/희소성: «이 [방법] 덕분에 놀라운 결과를 얻었지만, 대부분 모르는 이유가 있습니다.»

C 체크리스트: 첫 문장에 주제+대상+결과 · 숫자/감정/결과/궁금증 중 하나 · 초등학생 단어 · 1~2줄 말하듯 · 훅만 보고 끝까지 보고 싶은가. 팁: **같은 영상을 훅만 바꿔 2~3번 올려 본다** (→ 4번 Trial Reels).

C 생성 프롬프트(요지): «조회수 100만 이상 릴스를 분석하는 숏폼 전략가. 26가지 중 맞는 구조로 초반 3초 훅 10개. 짧고 강하게, 초등학생 단어, 첫 문장에 주제+대상+결과, 숫자·감정·결과·궁금증, AI 말투·뻔한 표현 금지, 1~2줄, 쓴 전략 표시. 입력: 주제 / 타겟 / 방향(정보·스토리·자극·감성·브랜딩).»

### 2. 대본 문장

B 규칙: 모든 문장에 기능이 있어야 한다. 파괴 / 이득 / 문제 / 군중 / 공감 / 행동유도 / 권위. 기능 없는 문장은 지운다. [파괴 → 이득 → 새 문제 → 이득+행동유도] 파도를 두 번 이상, 끝은 행동유도. 개념은 정의 말고 비유와 지위 상승으로(«AI 비서가 아니라 AI 직원»). 원본의 과장은 베끼지 않는다. 하마 kallaway 9칸(Hook → Lock-in → Body → Rehook…)과 같은 뼈대라 9칸을 바꾸지 않고, 칸마다 기능 태그를 다는 점검으로만 쓸 수 있다.

### 3. CTA 3단 (B)

키워드 → 보상 구체화 → 즉시성. «댓글에 ‘KEYWORD’» → «실제로 제가 쓰는 [자료]» → «바로 보내드릴게요». 하마 caption.md의 «Comment KEYWORD and I'll send you my GIFT»가 이미 이 꼴이다.

캡션 (B 5-3): 첫 줄 «저장 & 공유 필수!» → 훅 한 줄(**대본 훅을 그대로 쓰지 말고 영상에서 안 말한 부분을 궁금하게**) → 본문 3~5줄(이유 위주) → 📌 키워드 CTA → 해시태그. 하마는 11/08 승인 캡션 꼴(«If you…» 첫 줄)을 유지한다.

### 4. Trial Reels (D) — 하마에 없는 것

인스타가 팔로워가 아닌 사람에게 먼저 보여 주는 테스트 릴스. 약 24시간 뒤 첫 수치가 나온다. 쓰는 법: 바꾸는 건 하나만, 의미 있게. 예: A는 설명으로 시작, B는 완성된 결과로 시작. 같은 시간이 지난 뒤 비교하고, 여러 번 모아 패턴을 본다. 올릴 때 Trial 옵션이 보이면 쓴다.

### 5. 주간 역검증 (B 5-4, D 7단계)

- 조회수 순이 아니라 **비율 순**: 저장율 · 공유율 · 댓글율 · 팔로우 전환.
- 상위 3 · 하위 3을 훅 유형 · 포맷 · 주제 넓이로 «왜».
- 상위 댓글 5분류: 키워드 댓글(CTA 작동) · «나 얘기네»(포맷 작동) · 질문(**다음 기획 소재**) · 반박 · 팩트체크(어느 문장 때문인지).
- 다음 주 반복할 것 3 · 버릴 것 3.
- D 추적표: 영상 · 포맷 · 시험한 것 · 결과 · 다음에 할 것. 영상마다 올리기 전에 «이번에 알고 싶은 것» 한 줄.
- 도구: `/ig-audit`(배수·공유 순위), `/ig-reply`(댓글 분류). 숫자는 하림님이 인사이트에서 본 것만.

### 6. 레퍼런스 고르는 기준

- B: 2주 안에 10만 이상만. 조회수보다 저장·공유·댓글 비율.
- D·E: 큰 계정의 큰 숫자보다 **작은 계정이 평소의 몇 배**를 낸 것. 1만 평균에 20만이면 볼 만하다. 3배 이상이 신호, 1.5배 아래는 소음.
- D: 저장 폴더에 모으고 한 줄씩 «무엇이 나를 멈췄나». 구조·분위기·반전만 빌리고, 크게 빌렸으면 출처를 밝힌다.
- B 주제 넓이: 누구나 / 특정 타겟+넓은 주제 / 특정 타겟만. «특정 타겟만»은 버린다.
- B: 인스타에 자동 로그인해서 긁지 않는다(본계정 제한 위험). 찾을 땐 서브 계정이나 웹 검색.

### 7. Metricool (B) — 하림님 손으로 하는 세팅

- 무료: 브랜드 1개, 인스타·틱톡·페북·유튜브, 예약, 최적 시간 추천, 경쟁 계정 네트워크당 5개(**한 번 넣으면 수정·삭제 불가**), 분석 기록 1개월. Starter 월 약 3만 5천 원.
- 조건: 인스타가 프로페셔널 계정 + 페이스북 페이지에 연결. 메트리쿨에서 «Facebook으로 연결»을 써야 경쟁 계정 기능이 다 돈다.
- 경쟁 계정 등록 뒤 3~7일 데이터가 쌓여야 분석이 맞다. 틱톡은 경쟁 계정 미지원.
- B는 ChatGPT 플러그인으로 연결한다. Claude용 Metricool 연결은 **확인 안 됨**.
- 예약 게시는 Gaia 규칙 4(게시는 하림님)와 겹치므로 Claude가 걸지 않는다. 쓸모는 경쟁 계정 데이터와 하마 팔로워 활동 시간.

### 8. 얼굴 클론 (F) — 레시피만 담음, 하마에 쓸지는 미정

흐름: 내 사진 3장 → 새로 그린 셀카 1장 → 목소리 → 립싱크 영상 → 이어 붙이기. Claude Code가 도구를 부르고 결과를 확인한다.

- 셀카: Codex(ChatGPT 구독) 이미지 생성, 사진 3장 첨부. **기존 사진을 고치지 말고 매번 새로 그리게 한다**(고치기를 반복하면 얼굴이 변한다). 마음에 안 들면 프롬프트에 한 줄 더하고 다시. 얼굴 특징(점·귀걸이·앞머리)을 글로 적는다. 9:16 전면 카메라 셀카, 배경은 흰 커튼만, «No text, no logos», 과한 선명도 금지.
- 목소리: ElevenLabs eleven_multilingual_v2, stability 0.5 · similarity 0.75 · style 0 · speed 1.0, 만든 뒤 음높이 유지하고 1.2배. 30초 대본 약 200음절, 글자 수만큼 크레딧(283자 ≈ 283).
- 립싱크: Higgsfield MiniMax H3(사진+음성 → 영상). 15초 이하로 쉼에서 잘라(10·14·9초), 구간 앞에 0.5초 무음. **영상 안의 소리를 그대로 쓴다**(원음을 다시 깔면 입이 안 맞는다). 2K 초당 2크레딧, 3구간 66크레딧, 구간당 5~11분. 프롬프트는 표정 줄만 구간마다 바꾼다.
- 편집: 0.5초 무음 잘라 잇기, 긴 쉼 자르고 1.1배(31초 → 24초), 한 줄 자막, 요소 나올 때 작은 클릭음, −14 LUFS.
- 지킬 것: 내 얼굴·내 목소리만. AI 영상이라고 표지나 캡션에 밝힌다.

얼굴 일관성 3칸 시트 (G):
1. 정면 얼굴(무표정, 머리~어깨, 흰 배경, 세로 2000px 이상). 얼굴은 이 한 칸에만.
2. 전신 정면, 단순한 옷, 같은 조명. 다 되면 **목 위를 흰색으로 지운다**.
3. 전신 뒷모습, 정확히 뒤에서.
4. 가로 한 줄로 붙이고 높이를 맞춘다. 글자·번호 없음. 옷은 따로 «의상 시트»(사람 없이 옷만).
5. 넣을 때 프롬프트: «Use only the large face panel for her face» · «the faceless full-body panels are only for body shape» · «Ignore the clothes in the sheet» + 외모 한 줄.
이유: 10칸 시트는 칸마다 얼굴이 미세하게 달라 AI가 평균을 내서 «비슷한데 다른 사람»이 나온다. 표정은 시트 말고 프롬프트로 준다.

### 9. 계정 방향 (D)
