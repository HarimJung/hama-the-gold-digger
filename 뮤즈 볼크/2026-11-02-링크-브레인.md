# 링크 브레인 — 원본 + 상세 정리 (2026-11-02)

Taylor가 보낸 13개 고유 링크를 각각 원본 기준으로 정리한 새 파일. 각 섹션마다 원본 링크 + 자세한 설명이 함께 들어 있음.
요약이 아니라 구조·도구·순서까지 풀어씀. 인용은 짧게, 나머지는 내 말로 풀어씀.

> 클로드에게: 이 파일의 요약은 길잡이일 뿐, 기준은 원본이다. 실제 작업 전에는 해당 섹션의 원본 링크를 먼저 열어 원문을 확인할 것. 요약과 원문이 다르면 원문이 맞다. 요약만 보고 지어내지 말 것.

## 0. 연결 지도 — 이 링크들이 하나로 엮이는 방식

### 파이프라인 1: 얼굴 안 찍고 영상 만들기
사진 여러 장 → clone-me / Higgsfield Soul ID (얼굴 고정) → ElevenLabs 목소리 클론 → 립싱크 → Claude 영상 편집자 세팅(도구 5개 + 브랜드 시트)으로 편집 → OpenDesign Motion / 스토리보드 스킬로 모션·시나리오 추가.
- 얼굴 고정: clone-me는 본인 사진 3장 + 매번 새로 생성 (반복 편집하면 얼굴 틀어짐). Higgsfield Soul ID는 사진 5~20장으로 캐릭터 고정.
- 편집 뒷단: 영상 편집자 세팅 가이드(아래 1번)가 폴더·도구·프롬프트·스타일 시트까지 담당.
- 모션 대안: OpenDesign Motion(아래 4번)은 클로드 구독 없이 모션그래픽 만드는 경로.

### 파이프라인 2: 인스타 반자동화
말투 파일(voice.md) 먼저 → SNS 스킬 17개(글감·훅) → IG 에이전트 스킬 13개(릴스 대본·캐러셀 초안) → 알고리즘 세팅(도달 보호) → 게시는 직접.
- 솔직한 경계: 이 스킬들은 초안만 만들고 직접 게시하지 않음. 자동 팔로우·자동 댓글도 안 함. "자동화"는 초안 파이프라인 자동화지, 자동 게시가 아님. 네 룰(승인 전 게시 안 함)과 맞아떨어짐.
- 말투 파일이 출발점: SNS 스킬도 IG 스킬도 voice.md를 읽고 돌아감. 한 번 만들어두면 두 파이프라인이 공유.

### 파이프라인 3: 캐러셀 · 모션그래픽 · 아나토미
anatomy 다이어그램(개념 시각화) → Remotion / HyperFrames / OpenDesign으로 모션그래픽화 → SNS·IG 스킬로 캐러셀 기획.
- anatomy는 인터랙티브 웹페이지 형태라 인스타 캐러셀에 바로 올리려면 화면 캡처나 영상화 단계가 따로 필요함.
- 네 스타일(검증된 숫자 + 구조 설명)과 제일 잘 맞는 형식: UN/SDG 설명형 + 하마 돈 공부 설명형.

### 전체를 묶는 틀: 위임 루프
위 모든 걸 일회성이 아니라 반복 시스템으로 만드는 방법 (아래 11번). 일 하나에 매뉴얼 하나: 프로세스·툴박스·증명 3층. 네 HYOS 하네스 원칙(브리프·검증 관문·"알겠다"만으로 시작 안 함)과 같은 결.

### 링크 캡처 습관 (신영선 자료 공통)
릴스 저장/공유로 기록 → DM 링크 카톡으로 옮기기 → PC에서 AI 즐겨찾기 폴더 만들어 저장 → 바로 사용해보기 (미루지 말기, 제일 중요).

## 1. 클로드 코드로 나만의 AI 영상 편집자 만들기 (sdk-kim, 2026-11-02)

원본 링크: https://sdk-kim-builds.com/guides/claude-ai-video-editor-setup/?utm_source=instagram&utm_medium=dm&utm_campaign=claude-ai-video-editor-setup&utm_content=sdk_kim_builds&fbclid=PAVERFWAVVsr5leHRuA2FlbQIxMABwZG9mAmZkaWQWURcujqST1z18OuazlfzutF29doCHwHNydGMGYXBwX2lkDzEyNDAyNDU3NDI4NzQxNAABp5-bzDNeWGzzmEWOYlqV1Guif8xdqObr7q82y9E7O60DZ23JL-3MSHGVfkdJ_aem_luvEHue1zebRHHALgIFcZw

### 전제
- 클로드 데스크톱 앱이어야 함. 브라우저(claude.ai)에서는 내 컴퓨터 폴더를 못 읽음.
- 맥 또는 윈도우 컴퓨터, 촬영한 영상 한 편.

### 순서
1. 폴더 만들기: 바탕화면에 `AI 영상 편집자` 폴더 + 안에 3개 (원본 영상 / 레퍼런스 / 내보내기).
2. 폴더 연결: 클로드 앱 새 채팅 → 입력창 아래 프로젝트/폴더 버튼 → 폴더 선택 → Open → Allow. 입력창 아래에 폴더명이 보이면 성공.
   - 주의: 세션은 클라우드에서 돌아서 클로드가 쓰는 파일은 앤트로픽 서버에서 처리됨. 회사 기밀 영상은 넣기 전에 생각할 것.
3. 도구 5개 설치 (아래 표) + 각각 잘 되는지 확인까지 프롬프트에 넣기.
4. 스타일 정하기: 따라 하고 싶은 크리에이터 영상 3~5개 (또는 자기 예전 영상)를 레퍼런스로 → 브랜드 시트 만들기 (자막 모양·색·컷 리듬·효과음 정리 문서). 링크만 있으면 yt-dlp로 내려받기부터. 시트는 파일로 저장해서 다음 편집 때도 같은 기준 사용.
5. 편집: 원본 영상 폴더에 찍은 영상 넣고 편집 프롬프트 → 만들기 전에 스토리보드부터 보여달라고 할 것. 마음에 안 들면 편집자한테 말하듯 고치기 (예: 첫 3초 훅 자막 더 크게).

### 도구 5개
- Remotion: 리액트 코드로 영상 만들기 (자막·그래픽). 개인·소규모 회사 무료, 일정 규모 이상 회사는 유료.
- HyperFrames: HTML로 영상 만들기, AI 에이전트용. Apache-2.0. 주의: 영상 화면에 나온 hypergen/hyperframes 주소는 없는 저장소(404). HeyGen이 만든 거라 heygen-com/hyperframes가 맞는 주소.
- FFmpeg: 자르기·붙이기·인코딩, 모든 편집의 바닥. 오픈소스.
- Whisper: 음성 받아쓰기 → 자막. MIT.
- yt-dlp: 레퍼런스 영상 내려받기. Unlicense.

### 함정 2개
- "만들기 전에 스토리보드부터"를 빼면 바로 렌더부터 시작해서 마음에 안 들 때 처음부터 다시 기다려야 함. 스토리보드 단계에서 고치는 게 제일 쌈.
- 명령 실행 허용 창을 거절하거나 중간에 멈추면 클로드는 폴더를 못 읽은 상태로 대답만 함. 진행해달라고 답하고 허용 창을 거절하지 말 것.

### 낭만빌더 실제 편집 스타일 시트 (그대로 붙여넣어 브랜드 시트 기준으로 쓸 수 있음)
- 화면: 세로 1080x1920, 30fps. 장면 4종 섞기 (얼굴 전체 / 얼굴 위 카드 / 위 그래픽+아래 얼굴 분할 / 그래픽 전체). 화면은 2~3초마다 바뀜, 한 화면 글자는 적게. 첫 장면은 훅 — 주제를 은유하는 물건 하나를 3D로 크게. 대사가 "이 프롬프트", "이 화면"처럼 가리키는 건 실물(프롬프트 원문, 실제 앱 화면)을 띄움.
- 자막: 문장 단위로 한 화면, 화면 아래쪽 띠. 흰 글자 + 검정 테두리 + 약한 그림자. 핵심 단어 하나만 민트색 박스로 강조.
- 색: 배경 크림 또는 검정, 강조 민트.
- 세이프존: 글자·버튼은 화면 x 65~888, y 288~1248 안에만 (그 밖은 인스타·유튜브 계정명, 캡션, 오른쪽 버튼이 덮음).
- 컷과 소리: 말 사이 공백 자르기, 문장 사이 쉼 0.2~0.3초. 장면 바뀔 때마다 짧은 효과음. 배경음악은 템포 빠른 곡, 말보다 확실히 작게. 완성본 음량 -16 LUFS 안팎, 피크 -1.5dB 아래.
- 마무리: 마지막에 시청자가 할 행동 하나만 말하기 (댓글 키워드 또는 검색어).
- 작성자 판단: 처음부터 이 규칙을 다 줄 필요 없음. 레퍼런스로 시트 만든 뒤 편집본 보면서 거슬리는 것부터 한 줄씩 추가하는 게 제일 빠름.

### 자주 막히는 것
- "폴더를 읽을 수 없다" → 브라우저에서 하고 있는지 확인 (데스크톱 앱이어야 함).
- 설치 중간 멈춤 → 허용 창이 떠 있는지 확인.
- 레퍼런스 영상 못 받음 → 로그인 필요·비공개 영상은 yt-dlp로 못 받음. 영상 파일을 직접 레퍼런스 폴더에 넣기.
- 결과가 매번 다름 → 브랜드 시트 파일이 레퍼런스 폴더에 있는지, 프롬프트에 "레퍼런스 폴더의 스타일대로"가 들어갔는지 확인.

### 네 일에 연결
얼굴 영상 파이프라인의 뒷단. clone-me/Higgsfield로 만든 소스를 여기서 편집하고, 하마 30초 모션 릴스와 SDG 모션그래픽에 공용으로 쓸 수 있는 파이프라인.

## 4. OpenDesign Motion 시작 가이드 (Notion, 2026-10-20 확인)

원본 링크: https://nifty-licorice-663.notion.site/OpenDesign-Motion-AI-3fffd99f0e5f810e9731c2ed96e9b221

### 개념
- 클로드 모션의 오픈소스 대안. "클로드 없이 모션그래픽을 만드는 첫 순서"가 표방.
- 앱과 AI를 따로 고름: OpenDesign은 작업을 요청하고 결과를 확인하는 공간, 연결한 AI가 요청을 해석해 결과를 제작.

### 설치·연결
- 앱 설치: open-design.ai 다운로드. 맥 Apple Silicon·Intel 구분, 윈도우용 설치 파일. 앱 설치는 무료.
- 비용 구분 필수: 연결한 AI의 구독료나 API 사용료는 별도. 기존 AI 연결 방식과 OpenDesign 제공 모델 방식의 비용을 구분하고 시작.
- 연결 방법 3가지: (1) Claude Code·Codex 같은 코딩 AI를 이미 구독 중이면 쓰던 AI 그대로 연결 (구독료·사용 한도 그대로 적용). (2) 구독은 없지만 DeepSeek 같은 모델 제공자 API 키가 있으면 API 키로 연결 (쓴 만큼 과금). (3) 둘 다 없으면 OpenDesign 제공 모델 사용 (요금·조건은 공식 홈페이지에서 확인).
- 순서: 다운로드 페이지에서 OS 맞는 파일 선택 → 앱 설치·실행 → 실행 화면 확인한 뒤 연결 방법 선택 → 처음부터 긴 영상 말고 짧은 요청으로 연결 점검 (AI 응답 + 결과 파일 열림까지 확인).

### 데모에서 알 수 있는 것
- 공식 소개 영상은 같은 10초 소개 영상 요청을 두고 Claude Opus 5.5, GPT-6-Astra, DeepSeek V4.1 같은 모델과 Copilot·Qoder·Mistral Vibe·Hermes 같은 에이전트로 바꿔가며 다시 만듦. 바꿀 때마다 색·배치가 달라짐.
- 이걸 모델끼리 성능 비교 점수로 읽기보다, 사용할 AI를 선택하는 방식의 예로 보면 됨.
- 뒤에 나오는 한국어 요청문은 프롬왓 작성 응용 예시로, 공식 데모 원문 프롬프트와 구분됨.

### 네 일에 연결
클로드 구독 없이 모션그래픽 만들 때의 대안 경로. 얼굴 영상·캐러셀 모션의 모션그래픽 엔진 후보. 이미 클로드 Max/Ultra 쓰는 네 경우엔 (1)번 연결이 제일 자연스러움.

## 5. 스토리보드 프롬프트 빌더 스킬 (Notion, 존코바디자인)

원본 링크: https://warm-outrigger-c27.notion.site/401c9a1d314280ee8b28c547e05ddab1

### 설치
- storyboard-prompt-builder.skill 파일 다운로드 (Google Drive 링크). 안 되면 Drive 직접 링크로.

## 10. 인스타 알고리즘 세팅 가이드 — 필수 설정 5가지 + 추가 설정 + 키워드 최적화 (2026) (Notion)

원본 링크: https://soey.notion.site/5-2026-398e17f76d8281359feeed6e3d33898a

### 진입 경로
프로필 → 오른쪽 위 ☰ → 설정 및 활동.

### 본문에서 확인된 설정 (④까지)
1. 팔로우 요청 "검토를 위해 플래그 지정" ON: 설정 및 활동 → 친구 팔로우 및 초대 → 플래그 지정 토글 ON. 스팸으로 의심되는 프로필의 팔로우·요청에 자동 플래그 지정, 팔로워 리스트 별도 섹션으로 분리.
   - 왜 중요한가: 알고리즘은 "팔로워 수" 자체보다 팔로워 대비 반응 비율(도달률·참여율)을 봄. 봇·유령 팔로워가 쌓이면 게시물 올려도 반응 비율이 낮아져 추천 노출이 함께 줄어듦. 이 설정은 스팸 팔로워 정리를 자동화해 팔로워 품질을 지켜주는 장치.
   - 참고: 같은 화면의 "회원님이 팔로우하는 누구나 자동으로 확인"은 크리에이터·비즈니스 계정에는 적용되지 않는 옵션으로, 영상에서도 OFF 상태 유지.
2. 계정 공개 범위 = 전체 공개 유지: 비공개 계정의 게시물·릴스는 탐색 탭·릴스 탭·추천 피드에 아예 노출되지 않음. 비팔로워 도달이 0이 되므로 성장이 목적이라면 전체 공개가 전제 조건. 프로필 사진·사용자 이름 등 기본 정보는 어차피 공개되므로 콘텐츠 계정이라면 비공개로 얻는 이점이 거의 없음.
3. 공개 사진·동영상 검색 엔진 노출 허용 ON: 설정 및 활동 → 계정 공개 범위 → 해당 토글 ON. Google 같은 외부 검색 엔진이 내 공개 사진·동영상을 인스타그램 밖 검색 결과에 표시할 수 있게 허용. 2025년 중반부터 프로페셔널 계정의 공개 콘텐츠가 구글에 인덱싱되기 시작. 이 토글을 켜두면 인스타 앱 안에서만 소비되던 콘텐츠가 구글 검색 유입이라는 두 번째 노출 경로를 가짐. 구글 검색 결과에는 캡션 첫 줄이 제목(스니펫)처럼 노출되므로 키워드 최적화 전략과 시너지가 큼.
4. 미디어 품질 → "고화질로 업로드" ON: 업로드 시간이 오래 걸려도 항상 최고 화질로 업로드. 꺼져 있으면 네트워크 상태에 따라 화질이 자동으로 낮아짐. 릴스 확산의 최상위 신호는 시청 유지율. 뿌옇게 깨진 화질은 첫 3초 이탈(훅 실패)의 가장 흔한 원인 중 하나. 인스타그램은 반응이 좋은 영상에 더 높은 인코딩 품질을 유지해주므로 원본 화질을 최대로 넣는 것이 출발점.

### 본문에서 안 보인 부분 (솔직히 표시)
제목은 "필수 설정 5가지 + 추가 설정 + 키워드 최적화"인데, 읽은 본문 범위에서는 ④까지만 확인됨. ⑤번 설정, 추가 성장 세팅, 키워드 최적화 전략 본문은 이 범위에서 안 보임. 필요하면 페이지를 끝까지 다시 열어 확인할 것.

### 네 일에 연결
IG 자동화의 도달 보호막. 스킬로 좋은 초안을 만들어도 계정 세팅이 막혀 있으면 노출이 안 됨. 하마 계정에 바로 적용할 수 있는 체크리스트.

### 핵심 주장
일마다 에이전트를 하나씩 새로 만드는 방식은 그만두는 게 낫다. 대신 일 하나에 매뉴얼 하나를 만들고, 세팅하는 네 개의 프롬프트를 그대로 쓰면 된다.

- 왜 에이전트는 계속 죽는가: 에이전트마다 각자 프롬프트·도구·배선을 달고 있어서 일이 조금만 바뀌면 배선 어딘가가 부서지는데 그걸 발견하는 사람은 결국 당신.
- 사례: Vercel 데이터 팀이 전문가 에이전트들을 체인으로 연결해 직원들에게 줬더니 즉각 반응은 "형편없다"였다. 제대로 된 재구축은 더 똑똑한 에이전트가 아니었다. 범용 AI 하나에 자기들 파일 폴더와 평범한 도구 몇 개를 줬더니 내부 점수가 대략 두 배가 됐다. Anthropic 엔지니어들도 같은 선택을 했다. 처음부터 부족했던 건 지능이 아니라, 글로 적힌 당신의 업무 지식이었다.

### 시작 전에: 매뉴얼은 어디에 살고, 파일은 누가 쓰나
- AI가 내 컴퓨터 파일을 읽고 쓸 수 있으면(Claude Code 등) 실제 폴더를 만들면 됨 (예: ~/playbooks/weekly-client-update). 폴더 안에 SKILL.md를 만들고 파일을 저장하고 스스로 업데이트 — 동기화 기억할 일이 없는 복리 형태.
- 브라우저·데스크톱 앱의 Claude·ChatGPT를 쓰면 전부 할 수 있지만, Project에 올린 파일을 AI가 다시 쓸 수는 없음. AI가 업데이트된 SKILL.md나 새 템플릿을 화면에 출력하면, 먼저 실제 폴더에 저장한 뒤 올린 복사본을 교체하는 건 본인 몫. 예전 걸 지우지 않고 두 번째로 추가하면 안 됨. 같은 파일 버전이 두 개가 되는 순간 AI는 몇 주 전에 폐기한 지시를 따라가기 시작함.
- 클라우드 스토리지 경고: Dropbox·Drive에서 업로드하면 링크가 아니라 복사본이 만들어짐. 나중에 Drive에서 파일을 고쳐도 Project가 보는 것은 바뀌지 않음. 마스터 복사본은 정확히 하나, 모든 업로드는 마스터를 고치는 순간 낡아지는 스냅샷.
- 첫 일감 고르기 3가지 테스트: 주 1회 이상 하는 일 + 나쁜 버전을 한눈에 알아봄 + 새 직원에게 설명하는 데 20분 안에 끝남. 가장 복잡한 일로 시작하지 말고 가장 반복되는 일로 시작.

### 레이어 1: 프로세스
- 프로세스 레이어는 당신의 판단을 실제로 쓰는 순서 그대로 적어둔 것. 직접 타이핑하는 게 아니라 인터뷰를 받는 것. 일에서 절대 스스로 적지 않을 부분이야말로 결과물을 당신답게 만드는 부분.
- 좋은 SKILL.md 7요소: 한 줄짜리 목적, 언제 쓰는지(실제로 입에 담을 말로), 입력과 그 위치, 번호가 붙은 순서, 결정마다 그 근거가 되는 규칙, 완료의 정의, 예전에 당신을 태운 적 있는 예외 사례들.
- 인터뷰 프롬프트 요지: 반복하는 일을 나 없이도 돌릴 수 있는 매뉴얼로 만들어달라고 하고, 한 번에 질문 하나만, 최소 여덟 개 질문, 끝났다고 말하기 전까지 파일 쓰지 말기. 다룰 것: 시작 계기·빈도, 입력들과 정확한 위치, 실제 순서, 모든 결정과 그 뒤 규칙, 끝냈다고 부르기 전 확인 사항, 예전 예외 사례, 톤·기준, 나쁜 버전의 모습. 끝나면 [job-name] 폴더에 SKILL.md 작성 + 전체 파일 보여주고 "내가 뭘 잘못 뽑았는지, 알려주지 않은 게 뭔지" 묻기. 파일 직접 못 쓰면 쓴 척하지 말고 전체 내용 채팅 출력 + 파일명·위치 + 예전 복사본 지우고 교체 상기.
- 요령: 완전한 문장으로 답하고 추상 설명 대신 실제 예시. 짜증나는 질문이 보통 진짜 중요한 질문. 첫 버전은 80% 정도 맞을 거라고 기대. 고치는 건 채팅이 아니라 파일에서.

### 레이어 2: 툴박스
- 그 일에 필요한 재사용 가능한 모든 것을 폴더에 저장하고 SKILL.md가 그 파일들을 가리키게 함. 없으면 AI는 매번 같은 스크립트·템플릿·포맷 규칙을 처음부터 다시 지음. 시간·돈 나가고 결과는 매번 조금씩 다름.
- 들어갈 것: 기계적 단계를 수행하는 스크립트, 대괄호 자리표시자가 든 템플릿, 참조 데이터(고객 이름·표기, 제품 목록, 가격, 링크, 계정 ID), 만족했던 완성 작업 예시, 규칙 파일(브랜드 보이스, 포맷 표준, 절대 쓰지 않는 단어들), 자주 돌리는 하위 단계용 저장 프롬프트.
- 들어가면 안 되는 것: 일회성 산출물, 비밀번호나 키가 담긴 것, 반쯤 완성된 초안. 첫날 새 직원에게 주지 않을 것이라면 폴더에도 넣지 말 것.
- 통과한 산출물을 도구로 저장하는 법: 일을 AI와 한 번 돌리고 뭔가 제대로 나온 순간 그대로 얼리기. 재사용 가능 버전 요청 (내 상황에 특화된 부분은 자리표시자로, 아래에 채워진 예시 하나 참조로) → [job-name]/files/ 에 설명적인 이름으로 저장 (날짜·버전 번호 넣지 말기) → SKILL.md 업데이트해서 필요한 단계가 파일을 이름으로 가리키게 + 언제 쓰고 안 쓰는지 명시 → files/INDEX.md에 한 줄 추가 (파일명·용도·오늘 날짜). 일회성·비밀번호·미승인 초안은 저장 금지. 그리고 전체 일을 처음부터 다시 돌리고 어떤 저장 파일을 썼고 무엇을 백지에서 다시 지었는지 보고 — 다시 지은 것은 전부 툴박스 후보.
- 채워진 툴박스 실전 예시: 주간 고객 업데이트(숫자 뽑기 스크립트, 업데이트 템플릿, 고객이 칭찬했던 지난 업데이트 2개, 정확한 표기 client-names.md, tone-rules.md) / 콘텐츠 재활용(hook-bank.md, caption-template.md, brand-voice.md, 잘 나갔던 게시물 3개와 이유 메모) / 미수금 독촉(연체 단계별 이메일 템플릿 3개, escalation-ladder.md, account-contacts.md, 60일차에도 친절 유지 tone-rules.md) / 채용 서류평가(scorecard.md, role-brief.md, 점수 매긴 예시 답변 5개, rejection-email.md).
- 유지보수: 폴더 매달 검토. 안 쓴 건 지우고 용도 하나에 파일 하나만 유지. 거의 같은 일을 하는 파일이 두 개면 AI가 엉터리를 골라 씀.

### 레이어 3: 증명
- 거의 모든 사람이 건너뛰는 레이어. 90%만 완성된 결과를 내미는 AI와 끝난 결과를 내미는 AI의 차이가 여기서 남.
- 먼저 정할 것: 무엇이 증거로 인정되는가. AI가 자기 초안을 읽고 "괜찮아 보인다"는 건 가치 없음. 진짜 검증은 초록 바깥의 무언가를 만들어냄: 원본 파일까지 거슬러 올라가는 숫자, 살아있는 페이지를 돌려주는 링크, 렌더링 결과 스크린샷, 실제로 도는 테스트, 인용문과 대조한 주장, 단어 수, 참조 파일과 대조한 표기. 실패할 수 없는 검증은 검증이 아님.
- 검증 항목 프롬프트 요지: SKILL.md 완료의 정의 섹션에 이 일 특화 검증 항목 5~10개 추가. 모든 항목은 자기 의견 바깥 증거로 확인 가능해야 함. "명확한", "전문적인", "고품질" 같은 애매한 품질 단어 금지. 이 일을 마칠 때마다 내게 보여주기 전에: 검증 항목 전부 돌리기 → 실패한 것 고치기 → 다시 돌리기 → 항목마다 근거와 함께 한 줄 통과/실패 → 확인할 수 없는 것은 뭔지 왜인지 말하기 (통과한 걸로 가정 금지). 첫 패스에서 2개 초과 실패하면 멈추고 결과물 땜질 말고 어느 프로세스 단계가 원인인지 말하기. 파일 직접 못 쓰면 쓴 척하지 말고 전체 출력 + 파일명·위치 + 예전 복사본 교체 상기.
- 직무별 좋은 검증 예: 주간 고객 업데이트(모든 수치가 뽑힌 데이터 파일에 존재, 숫자 없는 형용사 금지, 200단어 이하, 고객 이름이 참조 표기와 일치, 지난주 약속 액션 언급) / 콘텐츠 재활용(훅 12단어 이하, 금지 단어 없음, 주장이 원본 전사 인용과 일치, 캡션 첫 줄이 결론이 아님) / 미수금 독촉(금액이 인보이스 기록과 일치, 만기일 정확, 톤이 단계에 맞음, 결제 링크가 열림) / 채용 서류평가(모든 점수가 지원자 답변 한 줄 인용, 근거 없는 점수 금지, 요약이 전사와 모순되지 않음).

### 루프: 채팅이 아니라 매뉴얼을 고쳐라
- AI가 뭔가 틀렸을 때 본능은 채팅에서 고치고 넘어가는 것. 채팅이 닫히면 교훈도 사라지고 다음 주에 같은 수정을 또 타이핑함. 루프는 모든 수정을 폴더에 다시 넣는 습관. 시스템이 쓸수록 좋아지고 에이전트는 쓸수록 나빠지는 이유가 이거.
- 진단 단계: 어느 레이어가 실패했는지 묻기. 순서에 단계가 빠지면 프로세스. 이미 있는 걸 다시 지었거나 저장된 파일이 틀렸으면 툴박스. 아직 없는 검증이 잡았을 실수면 증명.
- 고치기 프롬프트 요지: 결과물이 틀렸다고 정확히 지적 → 레이어 진단 두 문장 → 그 레이어에 가장 작은 내구성 있는 수정 (매뉴얼 전체 다시 쓰지 말기, 같은 실수 두 번이면 부드러운 리마인더가 아니라 명시적 규칙 추가) → notes.md에 오늘 날짜·잘못·바꿈 한 줄 → 같은 작업 처음부터 다시 돌려 수정 전후 비교.
- notes.md는 한 달에 한 번 읽기. 같은 레이어 반복 기록은 그 일이 진짜 어렵다는 뜻이고, 보통 다음으로 제대로 자동화할 가치 있는 일.

### 다 만들어진 폴더의 모습
- [job-name]/SKILL.md (목적·언제 쓰는지·입력·순서·결정·완료 정의·예외) / files/INDEX.md + 저장 파일들 / examples/날짜-good.md / notes.md (수정 기록, 최신이 위로).
- 모든 일을 위한 폴더 하나가 아니라 일 하나당 폴더 하나. 두 일이 계속 섞이면 문제는 각 SKILL.md 첫 줄. "언제 쓰는지"를 그 일을 시키고 싶을 때 실제로 칠 말 그대로 적기.

### 전체 실전 예제: 주간 고객 업데이트
- 프로세스: 지난주 숫자를 광고 대시보드에서 뽑고 계획과 비교하고 뭐가 바뀌었는지와 왜인지를 짚고 과장 없는 짧고 정직한 톤으로 쓰고 항상 가장 크게 움직인 숫자로 시작. 마지막 디테일은 아무도 쓴 SOP에 없는데 업데이트를 당신답게 만드는 게 바로 그거.
- 툴박스: 첫 실행이 숫자 뽑기 스크립트와 마음에 드는 구조를 만들어내니 둘 다 저장. 2주차에 보낸 고객이 답장해준 업데이트는 examples에. 고객 이름 표기와 계획 목표는 참조 파일로.
- 증명: 검증 5개 (모든 수치가 뽑힌 파일로 추적, 수치 없는 형용사 금지, 200단어 이하, 고객 이름 참조와 일치, 지난주 약속 액션 언급).
- 루프: 4주차에 데이터에 없는 숫자를 지어냄 → 증명 실패로 진단 → 모든 수치가 뽑힌 파일에 존재해야 한다는 검증 추가하고 기록 → 뒤로 한 번도 안 일어남. 6주차엔 쓰는 게 아니라 읽고 보내기만.

### 피해야 할 실수 5가지
1. 순서를 직접 적는 것 (인터뷰가 판단을 머리 밖으로 꺼내는 것).
2. 모든 걸 담은 거대 폴더 하나 (AI는 어떤 일인지 구분 못 하고 찍음).
3. 애매한 설명 ("콘텐츠 도와줘"는 필요할 때 절대 로드되지 않음. "언제 쓰는지"는 실제로 칠 말로).
4. 증명 레이어 없음 (검증 없으면 품질 관리는 당신 몫인데 그게 바로 넘기려던 일).
5. 채팅에서 고치는 것 (수정이 폴더에 없으면 다음 주에 또 타이핑).

### 첫 30분
가장 자주 하는 일감 고르기 → 인터뷰 프롬프트 돌리고 정직하게 답하기 (15분쯤) → 일을 한 번 돌리고 제대로 나온 걸 저장 프롬프트로 저장 → 검증 항목 추가 → 두 번째로 돌리고 설명이 얼마나 줄었는지 지켜보기. 두 번째 실행에서 클릭되니까 한 번으로 멈추지 말기.

### 네 일에 연결
위 모든 스킬·파이프라인을 일회성이 아니라 반복 시스템으로 만드는 틀. 네 HYOS 하네스 원칙(5줄 브리프, 검증 관문, "알겠다"만으로 시작 안 함)과 같은 결이라, 하마·SDG·AI 스킬 각 파이프라인마다 매뉴얼 폴더 하나씩 만들 때 그대로 쓸 수 있음.

## 13. 누끼토끼 clone-me (2026-10-31 글, 2026-11-01에 본문 전체 읽고 정리됨)

원본 링크: https://nookitokki.co.kr/clone-me

### 촬영 없이 얼굴 릴스 만드는 4단계
1. 셀카: Codex 이미지 생성에 본인 사진 3장 첨부, 매번 새로 생성 (반복 편집하면 얼굴 틀어짐). 구분되는 특징을 프롬프트에 이름으로 명시.
2. 목소리: ElevenLabs 복제 목소리. eleven_multilingual_v2, stability 0.5, similarity 0.75, style 0, speed 1.0 (1.0x로 렌더한 뒤 1.2x로 피치 유지 가속). 30초 내외 스크립트가 최적 (283자 ≈ 283크레딧).
3. 립싱크: Higgsfield MiniMax H3, 구간 15초 이하, 구간 앞 0.5초 무음 삽입, 내장 오디오 그대로 사용. 2K = 2크레딧/초 (작성자 3구간 66크레딧, 구간당 렌더 5~11분).
4. 마무리: Claude Code + ffmpeg — 연결, 무음 자르기, 1.1x, 한 줄 자막, 클릭음, 오디오 -14 LUFS.

### 규칙·필요 입력
- 규칙: 자기 얼굴 + 자기 목소리만 사용, AI 제작 표기 붙이기.
- 필요한 입력: 또렷한 얼굴 사진 여러 장 + ElevenLabs 목소리 클론 (목소리 복제에 필요한 샘플 수는 글에 없음 — 미확인).
- 달러 가격은 글에 없음.

### 네 일에 연결
얼굴 영상 파이프라인의 출발점. Higgsfield Soul ID (사진 5~20장, 얼굴 고정)와 같은 방향 — Soul ID가 캐릭터 고정, clone-me가 제작 순서. 완성된 소스는 1번 영상 편집자 세팅으로 편집하면 됨.
